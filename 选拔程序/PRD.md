# 项目 PRD

## 项目概述

做一个**实训室进组选拔程序**，把学院「学生实训室进组选拔流程」的 8 个环节（集中宣讲 → 实训室开放日 → 意向填报 → 导师初选与面试考核 → 拟录取与学生确认 → 分轮补录 → 统筹调剂录取 → 结果公示与正式入组）从线下纸质/群通知方式搬到线上，实现**双向选择、分轮录取、统筹调剂**的全流程数字化。

一句话目标：让学生在线填报与确认、实训室老师在线面试与录、学院调剂人员在线统筹补录与公示，全流程状态可追踪、结果自动计算。

## 目标用户

谁会使用它？

- **主要用户**：
  - **学生**：参加选拔、填报意向、确认去向的学生。
  - **实训室老师（导师）**：组织面试、给出拟录取/递补/内部调剂候选名单的实训室负责人。
  - **学院调剂人员**：公布剩余名额、组织分轮补录、执行全院统筹调剂、发布公示的学院管理员。
  - （管理员账号可由学院调剂人员兼任，负责基础数据与时间轴配置。）
- **他们现在遇到的问题**：
  - 意向、面试结果、确认状态分散在表格和群里，容易漏、容易改错。
  - 「收到 2 个及以上拟录取需自选唯一去向」「通期未确认视为放弃」等规则靠人工核对，冲突难发现。
  - 三轮补录 + 两级调剂（实训室内部调剂 → 全院跨实训室调剂 → 未服从调剂者统筹安置）的优先级手工排，耗时长且不可追溯。
- **这个项目要帮他们解决什么**：
  - 按角色分入口，各自只操作自己环节的表单。
  - 规则由程序判定：志愿冲突提醒、超时自动放弃、名额与递补顺位自动计算。
  - 每个状态变更留痕，公示名单一键导出。

## 核心功能

先列最重要的 3-5 个功能：

- **功能 1：意向填报（学生）**
  - 在「意向填报」时间窗内（示例：11月2日 08:00–12:00）最多填报 **3 个平行导师意向**，**不分志愿先后**。
  - 同时勾选两项调剂意愿：是否服从**实训室内部调剂**、是否服从**全院跨实训室调剂**。
  - 时间窗截止后锁定，不可修改；开放日/宣讲信息在学生端展示。

- **功能 2：面试与名单管理（实训室老师）**
  - 以实训室为单位统一组织面试（示例：11月2日 12:00 – 11月3日 17:00），无论报名是否满额，所有报名学生均参加。
  - 录入面试评价（考察学习态度、逻辑思维、编程基础、时间投入），产出三张名单：**拟录取名单、递补名单（含顺位）、内部调剂候选名单**。
  - 查看本实训室报名学生、意向归属与后续确认状态。

- **功能 3：拟录取确认与放弃判定（学生 + 系统自动）**
  - 仅收到 **1 个**拟录取意向的学生：系统**自动确认**。
  - 收到 **2 个及以上**的学生：在规定时间内（示例：11月4日 08:00–12:00）**自主选择唯一去向**。
  - **通期未确认视为放弃**，其名额自动按该实训室递补顺位补位。

- **功能 4：分轮补录（学院调剂人员 + 实训室老师 + 学生）**
  - 学院公布各实训室**剩余名额**；未被录取的学生重新填报志愿。
  - 实训室统一组织面试、双向确认与顺位递补，依次完成**第二轮、第三轮补录**（示例：11月4日 12:00 – 11月5日 17:00）。
  - 补录轮次由管理员按时间轴推进，各轮数据隔离、状态可回看。

- **功能 5：统筹调剂与结果公示（学院调剂人员）**
  - 三轮补录后剩余名额并入**全院调剂池**，按优先级统筹安排：
    1. 实训室内部调剂；
    2. 全院跨实训室调剂；
    3. 约谈未服从调剂的学生，作最终统筹安置。
  - 汇总最终录取名单并**公示（公示 1 天）**；公示无异议后学生正式入组，开展 AI+PBL 项目实训。

## 页面 / 模块结构

这个项目大概由哪些页面或模块组成？

- **页面 / 模块 1：登录与角色分入口** —— 学生 / 实训室老师 / 学院调剂人员三种角色，登录后进入各自工作台。
- **页面 / 模块 2：学生工作台** —— 流程时间轴总览、宣讲与开放日通知、意向填报表单、拟录取通知与唯一去向确认、补录志愿填报、最终结果查看。
- **页面 / 模块 3：实训室老师工作台** —— 本室简介与名额设置、报名学生列表、面试评分录入、三张名单（拟录取/递补顺位/内部调剂候选）维护、确认状态跟踪。
- **页面 / 模块 4：学院调剂人员控制台** —— 时间轴与轮次管理、各实训室名额与剩余名额看板、补录组织、调剂池排序与统筹安置、公示名单生成与导出。
- **页面 / 模块 5：公共信息区** —— 选拔流程 8 步说明、公告通知、公示页（学生只读）。

### 学生端详细交互流程

学生登录后始终停留在「学生工作台」，页面由一条**顶部流程时间轴**（8 个环节，当前环节高亮 + 截止时间倒计时）和**主内容区**组成；主内容区随环节推进自动切换，学生不能跳过或回退到已锁定环节（已提交内容可查看但不可修改）。

**S0 登录与进入**
1. 入口：学号 + 密码（或学院统一身份认证）登录；首次登录强制核对姓名、班级、手机号。
2. 登录后落地页 = 时间轴总览 + 当前任务卡片。当前无待办时显示「等待下一环节开始」与倒计时。
3. 异常：非本屆选拔名单内的学号 → 提示联系辅导员，不进入工作台。

**S1 集中宣讲 / S2 实训室开放日（只读浏览）**
1. 查看宣讲安排、各实训室介绍页（方向、导师、名额、培养与考核要求）。
2. 开放日提供各实训室参观场次与预约按钮（可选预约，不预约不影响后续填报）。
3. 介绍页底部提供「加入意向备选」书签，仅供学生自己参考，不构成志愿。

**S3 意向填报（关键写操作）**
1. 时间窗内（示例 11月2日 08:00–12:00）点击「填报意向」进入表单。
2. 表单内容：
   - 从实训室列表中挑选 **1–3 个平行导师意向**（列表展示剩余名额仅作参考，不分先后，无调剂优先级概念）；
   - 两个独立开关：**是否服从实训室内部调剂**、**是否服从全院跨实训室调剂**，默认均为「否」，需学生主动确认。
3. 提交前弹出核对页：列出所选意向 + 两项调剂意愿 + 规则提示（「平行志愿，面试全部参加；确认截止前可修改」）。
4. 时间窗内可反复修改，以最后一次提交为准；**到点自动锁定**，之后只读。
5. 异常分支：
   - 未填报且截止 → 状态记为「未参加首轮」，自动进入 S6 补录环节通知；
   - 选择 0 个意向但勾了调剂 → 允许，视为「只接受调剂」。

**S4 导师初选与面试考核（等待 + 参加）**
1. 学生收到面试通知卡片：本室统一面试时间、地点（示例 11月2日 12:00 – 11月3日 17:00），无论报名是否满额均需参加。
2. 页面显示「待面试 / 已面试 / 等待结果」三种状态；此环节学生无操作，只有查看。
3. 多个意向对应多个面试场次时，页面按时间列出全部场次并提示冲突（同室统一组织，一般不冲突；若冲突提示联系对应导师）。

**S5 拟录取与学生确认（核心分支判定）**
1. 结果推送后进入确认页，页面按录取数自动分流：
   - **仅 1 个拟录取**：页面显示「已自动确认」，无需操作，可查看去向详情；
   - **2 个及以上拟录取**：并列展示各去向对比卡片（实训室、导师、方向），学生必须在截止前（示例 11月4日 08:00–12:00）**点选唯一去向**并二次确认弹窗；截止前可改选，以最后一次为准。
2. **超时未选择 = 视为放弃**：所有拟录取资格作废，页面状态变为「已放弃，等待补录」，名额由对应实训室按递补顺位自动补位（学生端不展示递补细节）。
3. **递补规则（统一口径）**：原拟录取学生放弃/超时后，本室按递补名单顺位**逐位**通知；递补生获得与原拟录取相同的确认规则，确认截止使用**递补确认窗口**（时间轴配置项，见 A0.4，默认自递补通知起 2 小时内）。递补生再超时则**继续顺移**下一位；**递补名单耗尽后仍有空缺名额，该名额进入下一轮补录/调剂池**，不再停留在本室。
4. **已确认学生收到递补通知的冲突处理**：学生已在 C 室自动确认或自选确认后，又收到 B 室递补通知时，允许其在递补确认窗口内**改投 B 室**；改投即释放 C 室名额，自动触发 C 室按其递补名单顺位补位（链式处理，逐室留痕）。不改投则维持原去向，B 室继续顺移。

**S6 分轮补录（第二轮、第三轮）**
1. 学院公布剩余名额后，未被录取学生看到「补录志愿填报」入口（示例窗口 11月4日 12:00 – 11月5日 17:00，各轮独立计时）。
2. 表单只列出**还有剩余名额**的实训室；调剂意愿沿用 S3 的选择，可在本轮重新勾选。
3. 流程 = 重新面试 → 双向确认 → 顺位递补，交互与 S4/S5 相同；每轮结束页面明确显示「本轮未录取，进入下一轮」或「已录取，待确认」。
4. 三轮补录后仍未录取 → 进入 S7 调剂池，页面提示等待学院统筹安排。

**S7 统筹调剂（等待 + 可能的约谈）**
1. 学生看到自己是否进入全院调剂池、以及所处优先级（内部调剂 / 跨室调剂 / 未服从调剂待安置）。
2. 被调剂安置时收到通知卡片，展示最终去向；未勾选服从调剂的学生若被约谈安置，需在限定时间内确认（窗口由管理员在时间轴配置）。**调剂安置确认超时不触发递补**（调剂池无顺位链）：超时学生状态转为「安置超时待处理」，由学院调剂人员在线下约谈后手动登记终局状态（明确放弃 / 再次安置，见 A6.4），系统不自动判定。
3. 此环节学生原则上只读；确认动作仅在约谈安置分支出现。

**S8 结果公示与正式入组**
1. 公示页展示最终录取名单（公示 1 天），学生可见自己的姓名、去向实训室、导师。
2. 公示无异议后状态变为「已入组」，展示入组须知与 AI+PBL 项目实训安排。
3. 有异议 → 线下向学院反馈（首版不做在线异议提交，见「暂不做」）。

**贯穿性交互约定**
- 每个环节开始/截止前 30 分钟、5 分钟各发一次站内提醒（截止提醒对学生尤其关键）。
- 所有需要学生决策的按钮（提交志愿、确认唯一去向）都带二次确认弹窗，弹窗内复述规则后果（如「超时未选择将视为放弃全部拟录取」）。
- 学生端任何页面顶部倒计时以服务器时间为准，到点后相关表单按钮即时禁用并自动刷新状态。

### 实训室老师端详细交互流程

老师登录后进入「实训室老师工作台」，只见本室数据；页面结构 = 顶部环节进度条 + 待办卡片列表 + 各功能标签页。老师在流程中的职责边界：组织本室面试、产出三张名单、跟踪确认与递补，**不操作**名额发布、补轮推进和全院调剂（那是学院调剂人员的权限）。

**T0 登录与本室资料维护（宣讲前）**
1. 工号 + 密码登录；一个实训室可挂多名老师，角色分「室负责人」（可提交名单）与「普通老师」（仅录入评分）。
2. 首次使用核对/完善本室简介页：方向介绍、导师列表、培养与考核要求、**招录名额（老师填报提交）**；名额与简介的最终生效统一走「老师提交 → 学院调剂人员审核发布」一条链路（见 A0.3），发布前学生端不可见。
3. 异常：未绑定实训室的老师 → 显示「本室资料待管理员分配」，只读。

**T1 集中宣讲 / T2 开放日（只读 + 接待）**
1. 查看本室简介在学生端的展示效果（预览）。
2. 开放日场次管理：查看学生预约名单，可标记「已到场」；预约数据仅供参考，不影响录取。

**T3 意向填报期（等待 + 监督，不可干预）**
1. 实时查看报名本室的学生列表：姓名、班级、意向数（仅显示数字，不显示其他志愿内容）、两项调剂意愿勾选情况。
2. 页面明确提示：志愿填报截止前名单仍会变动，**此阶段不能做任何录取操作**。
3. 截止后名单锁定，生成「本批面试名单」，系统按统一面试窗口提示排期。

**T4 导师初选与面试考核（核心写操作）**
1. 面试名单页逐人录入：面试场次签到、四个维度评价（学习态度、逻辑思维、编程基础、时间投入，各为文字评语 + 分项记录，不做系统自动加权排名）。
2. 面试窗口截止前，室负责人在本室名单页产出**三张名单**：
   - **拟录取名单**：不超过名额数；
   - **递补名单**：明确顺位 1、2、3…（拖拽或上移/下移排序）；
   - **内部调剂候选名单**：面向报名本室但未录取、且勾选了「服从实训室内部调剂」的学生。
3. 提交前系统校验并高亮异常：拟录取人数 > 剩余名额；递补名单含已拟录取者；调剂候选未勾选对应调剂意愿；**同时反向核对——报名本室且勾选「服从内部调剂」但未进入任何名单的学生，系统列出提醒（该生将由学院在 A6 兜底处理，见调剂意愿对账清单）**。校验不通过可强制提交，但需填写理由并留痕。
4. 提交后名单进入「待学院生效」状态；同窗口内负责人可撤回重改。**学院退回通道**：管理员生效校验不通过时可退回本室名单，系统自动为该负责人临时重开名单编辑窗口（时长由管理员设定，操作全程留痕）；窗口外且未被退回的修改仍需联系管理员走同一通道处理。

**T5 拟录取与学生确认（跟踪 + 递补触发）**
1. 看板实时显示本室每名拟录取学生的确认状态：已自动确认 / 待自选 / 已确认 / **超时放弃**。
2. 出现「超时放弃」时系统自动按递补顺位补位，老师收到通知卡片并可一键发送递补确认提醒（递补学生的确认规则与学生端 S5 相同）。
3. 本室全部名额确认齐或窗口截止后，页面显示本室最终确认名单与剩余未招满名额数（剩余名额数据供学院发布用，老师本人不发布）。

**T6 分轮补录（重复 T3–T5，按轮隔离）**
1. 第二轮、第三轮补录期间，本室收到新的报名名单（仅含填报了本室剩余名额的学生），面试与名单产出流程同首轮。
2. 每轮页面显示轮次标签（第一轮 / 第二轮 / 第三轮），历史轮数据只读可回看。
3. 递补在本轮内继续按顺位自动触发，规则同 T5。

**T7 统筹调剂（配合角色）**
1. 本室若有剩余名额进入全院调剂池，老师在调剂页只读查看：调剂池状态、学院拟调入本室的学生列表（含其调剂意愿来源：内部调剂 / 跨室调剂）。
2. 首版设计：跨室调剂由学院调剂人员直接安置，**不需要老师接收审批**；老师可在公示前对安置结果提出异议（线下反馈，系统仅记录备注字段）。

**T8 结果公示（只读）**
1. 查看本室最终录取名单，核对无误后页面提供「导出本室名单（Excel/CSV）」用于线下归档。
2. 公示期结束收到流程结束通知，本室数据整体转为只读归档态。

### 学院调剂人员端详细交互流程

调剂人员登录后进入「学院调剂人员控制台」，可见全院数据；页面结构 = 全局时间轴控制条（当前环节 + 一键推进/回退需二次确认）+ 名额看板 + 各功能标签页。该角色对流程拥有最高写权限：配置时间轴、发布名额、推进轮次、执行调剂、生成公示。

**A0 登录与基础数据准备（宣讲前）**
1. 管理员账号登录。
2. 导入学生名单（Excel 模板：学号、姓名、班级、手机号），系统校验重复与缺列并输出导入报告。
3. 创建/维护实训室：名称、方向、导师绑定。**招录名额统一链路**：老师在 T0 填报提交名额与简介 → 管理员审核 → 点击「发布」生效（学生端才可见）；管理员可直接代改名额，但视为发布前编辑且全程留痕，不另设第二条生效通道。
4. 配置本届时间轴：8 个环节 + 三轮补录的各窗口的起止时间（对应 PRD 示例日期，可整体调整），并含**递补确认窗口**配置项（递补/顺位补位的确认时限，默认自递补通知起 2 小时，可改为独立时段）；保存前系统校验时序合法性（如补录第二轮必须晚于确认窗口）。

**A1 宣讲 / 开放日（发布与监控）**
1. 发布全院公告（宣讲安排、开放日须知），学生与老师端同步展示。
2. 监控页查看：各室资料完成度、学生登录覆盖率，用于线下催办。

**A2 意向填报期（监控）**
1. 实时看板：各室报名数/名额、报满与冷门室分布、两项调剂意愿的全院比例。
2. 截止后一键（或按时间轴自动）锁定全部志愿，生成「面试组织总表」供各室使用。

**A3 面试与名单产出期（催办 + 生效）**
1. 看板跟踪各室三张名单提交进度，未提交室高亮，可发送站内催办。
2. 收到老师提交的名单后执行**生效校验**：全院拟录取总数不超名额、跨室重复拟录取仅提示不阻止（双向选择允许一人多录，这正是 S5 自选分支的前提）。**校验不通过 → 管理员退回该室名单并填写原因，系统自动为该室负责人临时重开编辑窗口（同 T4.4 退回通道），退回与重开均留痕**；全部室名单通过校验后方可发布。
3. 全部名单生效 → 点击「发布拟录取结果」，学生端同时进入确认环节（仅 1 个录取者由系统自动确认，多录取者进入限时自选）。

**A4 确认窗口（监控 + 自动判定）**
1. 实时确认看板：自动确认数 / 待自选数 / 已自选数 / 超时放弃数 / 递补触发次数。
2. 窗口截止 → 系统自动执行：未自选者判放弃、按顺位递补（递补确认使用 A0.4 配置的递补确认窗口）；**递补超时逐位顺移，递补名单耗尽后空缺名额自动滚入下一轮补录/调剂池**（统一口径，与学生端 S5.3 一致）；已确认学生收到递补通知的改投处理同 S5.4，链式释放原室名额并触发原室顺移。全部完成后各室剩余名额自动汇总。
3. 异常处理：学生因不可抗力申请恢复资格 → 管理员可在日志留痕前提前重开该生的单人确认窗口（全院批量重开不允许）。

**A5 分轮补录组织（第二轮、第三轮）**
1. 点击「公布剩余名额」，学生端进入补录志愿填报窗口；表单仅开放尚有余量的实训室。**可参与对象 = 所有未确认入组的学生，含首轮未填报者（S3.5 的「未参加首轮」状态，与学生端口径统一）**。
2. 每轮流程 = 公布名额 → 学生重填 → 老师面试出名单 → 双向确认与顺位递补，控制台按轮推进，轮次间数据隔离。
3. 轮次截止后系统自动汇总：本轮录取数、仍未录取人数、最新剩余名额；两轮补录都结束才进入 A6。

**A6 统筹调剂录取（核心写操作）**
1. 三轮补录后，剩余名额自动并入**全院调剂池**；页面按优先级生成三段待安置清单：
   - 第一优先级：各室内部调剂候选名单中未录取者；
   - 第二优先级：勾选服从全院跨实训室调剂的未录取者；
   - 第三优先级：未服从调剂的剩余学生（约谈对象）。
   **调剂意愿对账清单**：系统自动比对「勾选了服从内部调剂但未进入任何室候选名单」的学生（对应 T4.3 反向核对），此类学生兜底并入第一优先级末尾单独标注，由管理员安置时自行决定去向室，避免静默漏排。
2. 安置操作：将学生拖入/指派到某室剩余名额，系统实时校验名额余量并显示该生志愿历史与调剂意愿来源。
3. 第三优先级支持登记线下面谈结果（备注 + 安置去向）；被安置学生收到确认通知，在配置的安置确认窗口内确认。**安置确认超时不自动递补、不自动判放弃**：状态转「安置超时待处理」，由管理员约谈后手动登记终局（再次安置 / 明确放弃），与学生端 S7.2 口径一致。
4. 全部学生状态到达终局（已安置 / 明确放弃 / 无名额可安置留档）后，方可进入公示。

**A7 结果公示与归档**
1. 一键生成最终录取名单公示页（全院、按室分组），设定公示期（示例 1 天）并发布。
2. 公示期内如有线下异议，管理员可撤回公示、修改名单并留痕后重新发布（公示期重新计时）。
3. 公示无异议 → 点击「确认入组」，学生状态批量变为「已入组」，展示入组须知；导出全院总表归档，本届数据整体转只读。

**A8 贯穿性权限与留痕约定**
- 所有推进类操作（锁定志愿、发布结果、开启下一轮、进入调剂池、发布公示）均需二次确认弹窗，弹窗内列出受影响人数。
- 关键写操作全部进操作日志（操作人、时间、对象、前后值），日志只可查不可删。
- 时间轴到点自动执行与手动推进并存：自动为主，手动仅限管理员补救且留痕。

## 设计与体验要求

希望它看起来和用起来是什么感觉？

- **视觉风格**：校园教务系统风格，干净、可信、低装饰；流程状态一目了然（参考流程图的 8 步时间轴表达）。
- **字体 / 色彩 / 间距偏好**：中文无衬线字体；主色深蓝 + 橙色强调（与流程图配色一致）；关键操作按钮大、留白充足。
- **需要适配的设备**：桌面端为主（老师与管理员录入），**手机端必须可用**（学生填报与确认多在手机上完成）。
- **参考设计稿、截图或链接**：本目录 `mmexport1794203798244.jpg`（选拔流程图）、`638e584f29074cea0bb641450a5ddcf7a56486fc92144a9df4f49cc6f3ac9726.png`（PRD 模板）。
- **体验要点**：
  - 学生首页顶部常驻「当前所处环节 + 截止时间倒计时」。
  - 收到多个拟录取时，确认页用醒目对比卡片展示各去向，避免误选。
  - 所有截止时间到点自动生效（锁定/放弃/进调剂池），不依赖人工触发。

## 技术约束

有哪些已经确定或不希望改动的地方？

- **技术栈**：Web 应用；前端 React + TypeScript（或 Vue 3，二选一后不再混用）；后端 Node.js（Express/NestJS）+ MySQL；部署到学院可用服务器即可。
- **不要改动的文件 / 路由 / 组件**：首版为独立新项目，无历史代码约束；流程 8 环节的名称与顺序以流程图为准，不在程序内随意增删。
- **优先使用的组件库或样式方案**：Ant Design（桌面端表单密集场景）+ Tailwind CSS（学生端移动端页面）；图表/看板可用 Ant Design Charts。
- **其他约束**：
  - 时间窗以配置驱动（日期时间可在管理端调整），不硬编码示例日期。
  - 名单、确认、调剂等关键写操作需记录操作日志（谁、何时、改了什么）。

## 验收标准

做到什么程度才算完成？

- **核心流程可以跑通**：按 8 环节时间轴推进一遍完整选拔，覆盖以下规则且结果正确：
  1. 3 个平行志愿、不分先后；调剂意愿两项独立勾选。
  2. 单拟录取自动确认；多拟录取限时自选唯一；超时自动放弃并触发递补。
  3. 三轮补录依次进行，剩余名额自动进入全院调剂池。
  4. 调剂优先级：内部调剂 > 跨实训室调剂 > 未服从调剂者统筹安置。
  5. **递补链闭环**：递补超时逐位顺移、名单耗尽后名额滚入下一轮；已确认学生改投递补时原室名额链式释放并触发原室顺移；递补确认截止按 A0.4 配置的递补确认窗口判定。
  6. **名单退回通道**：管理员生效校验不通过可退回室名单并临时重开该室编辑窗口，退回—修改—重新提交—再生效全程留痕。
  7. 公示名单可由三个角色分别查看/导出，导出内容与系统内一致。
- **手机端和桌面端都能正常浏览**：学生端在手机（375px 宽）上可完成填报与确认全流程。
- **视觉效果接近设计稿或参考图**：流程时间轴、配色与参考流程图观感一致，无明显报错和布局错位。
- **权限隔离**：三种角色只能看到和操作各自范围内的数据（老师看不到他室评分明细，学生看不到他人志愿原文）。

## 暂不做的事情

哪些需求先不做，避免项目变复杂？

- **暂不做**：
  - 在线视频面试 / 面试直播。
  - 与教务系统的成绩、学籍自动同步（首版手动导入学生名单）。
  - 短信 / 企业微信推送（先用站内通知）。
  - 面试评分的加权算法与自动排名（老师人工定名单，系统只记录和排序展示）。
  - 多届次/多学期并行选拔（首版只支持一届一次）。
- **以后再考虑**：
  - 公示期在线异议提交与处理流。
  - 选拔数据分析看板（各室报录比、调剂流向）。
  - 学生能力画像与导师匹配推荐。
