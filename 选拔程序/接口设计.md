# 实训室选拔程序 · 接口设计

基于 `PRD.md`（S/T/A 流程坐标）与 `数据库设计.md`。后端 Node.js + TypeScript，REST API，前缀 `/api/v1`。

## 0. 通用约定

- **认证**：JWT Bearer Token；`role` 声明为 `student | teacher | admin`，老师另带 `labId` 与 `labRole(lead|member)`。
- **权限守卫**：`@Roles()` 粗粒度 + `@LabScoped`（查询自动注入 `WHERE lab_id = 本人绑定室`，老师端）+ 服务层细粒度（窗口期、状态机前置态）。越权统一 `403`，跨室资源访问返回 `404`（不泄露存在性）。
- **时间**：所有窗口判定用服务器时间；响应内窗口类资源附带 `serverTime` 与 `deadlineAt`，前端倒计时以此为准（S 贯穿约定）。
- **推进类操作**（锁定、生效、发布、开轮、进池、公示）：请求体必须带 `confirm: true`（对应二次确认弹窗），响应返回 `affectedCount`（A8 弹窗展示人数）。
- **幂等**：学生决策类接口（提交志愿、点选去向、改投）带 `Idempotency-Key` 头；名单/安置等写接口以状态机前置态做天然幂等（重复提交返回 `409`）。
- **错误码**：`400` 参数/校验失败（返回 `violations[]` 明细，对应 T4.3 高亮异常）；`409` 状态机冲突（如窗口已锁、名额不足）；`422` 业务规则拒绝（如超 3 志愿）。
- **审计**：所有 POST/PATCH 成功路径在同一事务写 `audit_logs`（含 `affectedCount`），无例外清单。

### 窗口守卫（贯穿所有写接口）

写操作前统一校验 `stage_windows`：`now ∈ [start_at, end_at]` 或存在管理员补救授权（`reopened_until`、单人窗口重开）。失败返回：

```json
{ "code": "WINDOW_CLOSED", "stage": "wish", "round": 1,
  "window": { "startAt": "...", "endAt": "..." }, "serverTime": "..." }
```

## 5. 系统自动任务（无对外接口，行为契约）

| 任务 | 触发 | 动作 | 落点 |
|------|------|------|------|
| 窗口锁定 | `wish.end_at` | 批量 `wish_forms.status=locked`；未填报者 `student_states=not_participated` | S3.4/S3.5 |
| 确认超时判定 | `confirm.end_at` | `pending`→`timeout_waived`；按 `rank_no` 生成 `waitlist_promote` offer（deadlineAt=递补窗口）；**顺移至名单耗尽后剩余名额滚入下轮/调剂池** | S5.3 统一口径 |
| 递补链维护 | 任一 offer 变 `declined_by_switch/timeout_waived` | 同事务：释放名额→本室顺移→若涉及已确认学生改投则链式触发原室顺移 | S5.4 |
| 进调剂池 | 第 3 轮 `makeup_confirm.end_at` | 汇总剩余名额入池；按三级优先级 + 对账清单生成 `adjust_pool` 行 | A6.1 |
| 安置超时 | `placement_confirm.end_at` | 仅转 `timeout_pending`，**不做任何自动递补/判放弃** | A6.3 |
| 提醒 | 各窗口 `end_at - 30/5min` | 定向生成 `notices`（deadline_reminder） | S 贯穿约定 |

所有任务实现要求：**可重入**（按当前态判定，重复执行无副作用）、写 `audit_logs(actor=system)`、单批事务 ≤500 行。

## 6. 核心时序（两个最复杂流程）

**多录取自选 + 递补改投链**
```
A3 publish-results → offers: [B:pending, C:pending] (deadlineAt=T)
学生 choose(B) → B:auto_confirmed/chosen, C:cancelled
C 室窗口截止 → C 位1递补 offer → 学生(已确认B) accept-waitlist(改投)
  事务内: B→declined_by_switch; B室顺移生成新offer; 学生→C confirmed; confirmations(switch)
```

**名单退回通道**
```
T submit → pending_effect
A3 校验失败 → POST /admin/lists/{id}/return {reason, reopenHours:4}
  → status=returned, reopened_until=now+4h, notice(lead)
lead 在重开窗口内 PUT members + POST submit → pending_effect（全程 audit）
```

## 7. 与 DB 的映射检查

- 每个写接口标注的「落点」均对应 `数据库设计.md` 的表/状态字段，无悬空接口。
- `choose/accept-waitlist/place` 三处名额写操作统一走 `lab_quotas` 行锁服务（`SeatService.reserve/release`），避免超员路径分散。
- 学生状态机 `student_states.state` 只允许由上述接口与自动任务迁移，禁止直接 PATCH。
